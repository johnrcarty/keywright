# Keywright 0.0.2 — Expanded integrations and project work

Release candidate — prepared for review; not yet published.

Keywright 0.0.2 expands the integration catalog and makes it easier to connect services,
set up remote CLIs, and bring GitHub work into native project boards. Connections use
Keywright's existing access policies, approval controls and audit trail.

## Expanded integrations

- **GitHub:** named personal access token connections, a compact repository picker with
  quick and bulk Add/Ignore actions, and persistent ignored-repository preferences.
  Import issues into project boards with repeatable inbound synchronization, visible sync
  status and source-state tracking. Local notes, assignments and board placement survive refreshes.
- **Browser sign-in:** guided OAuth setup for Notion, CoinStats and Robinhood, with
  provider-specific setup guidance and connection management. Provider eligibility and
  account permissions still apply.
- **Remote CLI setup:** Coinbase CLI connections and guided DoorDash installation and
  headless sign-in on an existing enrolled SSH host. CLI execution stays on the selected
  host, separate from the broker.
- **Homelab connectors:** built-in read-only tools for Proxmox VE, Pi-hole v6,
  Home Assistant, Jellyfin, Sonarr, Radarr and authentik. Existing Omada and inventory
  integrations remain available alongside custom SSH, MCP and LLM connections.
- **A unified resource list:** GitHub connections appear under All / Other, with search,
  sorting and a direct route back to repository discovery.

## Project work and knowledge

- Persistent General and project task boards, plus cross-project **All tasks** and
  **Needs you** views. Local tasks, comments, assignment, activity and notifications
  remain durable independently of notification dismissal.
- Repository records with dev, test and production locations linked to existing hosts.
  Saving a location records metadata; explicit verification uses existing host access controls.
- Board-scoped task and repository operations through the API, MCP and CLI.
- A knowledge graph with references, backlinks and local views. It recognizes Markdown
  links, wikilinks and plain internal document paths in note text and source metadata.
  Rebuilding links preserves published content and review history.

## Upgrade notes

Server, client and optional mail router share version **0.0.2**. Upgrade the server and
client together to use the new commands and interfaces. The base installation still
supports SQLite and does not require PostgreSQL, Redis or another frontend service.

Before upgrading, stop the broker and back up its complete data directory, including
SQLite state, keys and canonical knowledge Markdown. Retain the previous image and
configuration. Startup adds the new tables and columns and seeds the permanent General
board idempotently. Use **Knowledge → Knowledge graph → Index links in existing documents →
Rebuild document links** to include the newly recognized reference formats in older notes.

After publication, use the release's checksum-verified installation bundle for an image
pinned by digest. Upgrade Python packages to `keywright==0.0.2`, `keywright-server==0.0.2`
and, where used, `keywright-router==0.0.2`.

## Current limits

GitHub sync is inbound-only: local changes do not update GitHub issues or comments.
GitHub App onboarding, webhooks and GitHub Projects sync remain future work. Task claims,
execution handoffs and automatic agent launching are not included in this release.
Repository setup does not clone, build or deploy code. Homelab connector tools are read-only.
The supported broker topology remains one worker with one SQLite file.

Knowledge connections are explicit references, not automatically inferred topic or semantic
relationships. Optional integrations require their own service access and configuration.
